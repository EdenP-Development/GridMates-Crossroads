# ARTREADY-38 — Crossroads original art system and first production batch

**November 18, 2026 · Draft, stacked on GAMEPLAY-37.**
**Goal:** A real mobile tabletop game, not a collection of Compose/HTML-looking placeholder cards. Build one coherent woodland visual language while protecting readable movement, accessible controls, saved games and LAN.

## What is implemented now

The Android app can load **optional, versioned, local PNG artwork** from `app/src/main/assets/art/v1/` through `CrossroadsArtAssets.kt`. The existing code-drawn design remains on screen when any individual image is absent or cannot decode. No network calls, runtime image generation, mandatory download, new account or new game rule has been added.

Existing features remain authoritative: board geometry and camera, numbered player seats, colored player rings, action button labels, fork risk and event information, results/wins, old and experimental saved matches, and household LAN.

### Asset paint order

1. **Course backplate:** either the approved scenic PNG or the original Compose woodland drawing.
2. **Always generated by the engine:** route network, start/finish, nodes, risk rings, labels, current progress, decision focus.
3. **Token layer:** original tactile ring/shadow, optional 512 px transparent portrait *inside* the ring, then mandatory white player number above it.
4. **Action panel:** readable choice text/buttons stay native; optional small shelter/hazard/mischief illustration sits alongside the text, not instead of it.
5. **Home/results:** optional authored panorama/banner replaces or precedes nonessential decoration only. Starting the game and viewing the winner remain functional without artwork.

Important: A board background **MUST NOT contain drawn path lines, playable nodes, risk icons, text, arrows, dice or pieces.** The real interactive graph is overlaid at runtime at a precise position and needs to remain legible regardless of crop/zoom. Scenery is visual context only, not a hidden game state.

## Locked first-pass visual direction

**"A tiny woodland race played on a beautifully printed tabletop."** Warm, inviting, hand-authored, slightly nostalgic and polished—like a modern illustrated family board game placed on wood, **not** generic app forms, stock fantasy art, shiny 3D MMORPG scenery or AI faux-HTML. The game should be comfortable for older/nontechnical players as well as children.

- **Palette:** parchment `#F7F0DE`, deep forest `#48684D`, bark `#80664B`, muted warm gold `#D9B872`, creek blue `#8FBCC3`. These are guidance, not an excuse to ignore accessibility.
- **Rendering:** **match the existing GridMates Woodland cut-paper editorial portrait family**: broad flat natural-color shapes, confident deep forest-green contour, cream highlights, restrained soft tabletop shadows, simple species silhouettes. Backplates may have subtle paper/wood grain, but no generic painterly stock texture, hyperrealism or extra shading on character portraits. Keep low-contrast scenery behind mechanics.
- **Regions:** Meadow (flowers, open grassy light), Forest (canopies, firs, bridge/stream motifs), Village (cottages, orchard, fence). Cedarwood gets denser forest and warm expedition camp details; Brookside is brighter and creek-led.
- **Lighting:** warm, soft daylight with lightly dimensional tabletop shadowing. Avoid dramatically dark forest, heavy bloom, hyperrealism, glitter and overcomplicated UI chrome.
- **Hierarchy:** the board remains the hero; dice, player color/number, current decision and the actual road geometry must be far clearer than environmental decoration.
- **Consistency:** the same illustration language applies to home panorama, three boards, 3 encounters, finish banner and token portraits. Reject an individual beautiful asset if it does not belong to the set.

## Verified sibling artwork that can guide the style (NOT copied yet)

**GitHub source inspected on November 18, 2026:** [GridMates Sudoku main](https://github.com/PlayerEden/SudokuTogether) contains **12 packaged Woodland portraits**, plus their originals, original/resource SHA-256 mappings and prompts: [packaged-assets.json](https://github.com/PlayerEden/SudokuTogether/blob/main/design/woodland/packaged-assets.json) and [generation.json](https://github.com/PlayerEden/SudokuTogether/blob/main/design/woodland/generation.json).

The existing **Owl + Fox** are the strongest visual references. Their documented style is *flat editorial cut-paper artwork, forest-green outlines, warm cream and muted ochre, head-and-shoulders, transparent square crop, legible at 48px*. Other existing Woodland subjects include squirrel, tortoise, rabbit, badger, bear, deer, robin, otter, hedgehog and cat.

**Reuse gate:** Those files were generated for Sudoku's collection and have provenance/hashes, but Crossroads does **not** yet have an explicit approved cross-project redistribution/licensing entry in its own manifest. Do **not** copy them, assign new collection ownership, or claim player unlocks. If reusing a portrait for a Crossroads seat, explicitly approve that source, verify terms, export a 512 × 512 transparent variant, record the *new* file SHA and original source in Crossroads' manifest, then rerun QA. The shared art language is allowed as design guidance independently of transferring binary files.

For other assets, use Owl/Fox as visual reference, **not** an invitation to copy fox ears or owl feather patterns onto other species. Create scenery and event illustrations in the same simplified print/contour family.

### Recommended first art batch

**Batch A: four images only.** Establish the shared illustration style with `home_hero.png`, `board_woven.png`, `event_shelter.png`, and `event_hazard.png`. Test these together in a signed QA APK *before* making nine variations. An authentic art system is more valuable than 12 unrelated generated pictures.

1. **Home hero:** Wide tabletop vista with several separated woodland paths winding toward a cozy village, tactile board-game material, soft creek and trees. No readable route signs, characters with licensed likenesses, numbers or UI text. Open, calm composition with visual focus.
2. **Woven backplate:** Top-down hand-painted parchment forest-map background with meadow left / woodland creek center / village right. Low-contrast scenic illustration **only**; no playable paths, markers or labels. Avoid strong high-contrast lines that could look like fake roads. Keep margins simple for camera panning.
3. **Shelter event:** A tiny woven-roof woodland waystation, supplies, lantern and trail shelter on warm parchment, in the same outlined/rendered style as the board. Readable as a 62 dp thumbnail.
4. **Hazard event:** An unstable but family-friendly rocky ridge / old bridge plank, small leaves in motion, a clear sense of risk without violence or disaster imagery. Same light, linework, texture, border treatment and framing as Shelter.

Review all four *next to one another* for identical palette/outline/material. Revise style as a set; do not silently accept a mismatched first batch.

### Future batches

**Batch B:** Brookside and Cedarwood backplates with the same paper/wood/creek vocabulary. **Batch C:** matching four-token miniature set—keep colored seat ring and printed number above the art for accessibility. **Batch D:** mischief and victory banner. Avoid making art a prerequisite for checking whether the v3 gameplay loop is fun.

## How to introduce a real approved image

1. Create/export an **8-bit RGB or RGBA PNG**, matching the manifest dimensions; tokens must be transparent RGBA. Never embed route data, active UI text or third-party watermarks.
2. Add the exact lowercase file to `app/src/main/assets/art/v1/`. Avoid duplicate suffixes like `(1)`, alternative spelling or unregistered files.
3. Update its row in `manifest.json`: `status: "approved"`, `origin` (actual source project or human-created/generator trace), `license` (`original`, `commissioned`, `generated`, or `licensed` **after human verification of redistribution terms**), and lowercase SHA-256 of exact image bytes.
4. Run `python3 tools/check_crossroads_art_pack.py`. The checker rejects missing rights metadata, unapproved files, wrong dimensions, corrupted PNG structure, SHA mismatch, oversized PNGs and unregistered assets. It uses only Python standard library. **This cannot independently determine whether an artwork license is legally valid.**
5. Use the GitHub Android QA workflow to build a signed install-over APK. Check the real Android screen at phone size and large system fonts. Inspect whole board (1×), manual zoom (up to 3×), short phone, active action panel, fork targets and finished results.
6. Record visual acceptance and provenance. If legibility suffers or the picture mismatches the art bible, improve the PNG. The code-drawn fallback remains available by removing that image and marking the slot planned, without touching game data.

Optional art budget: **≤8 MiB per PNG; ≤32 MiB for this pack**, enforced in CI. These are quality limits, not goals. Optimize image bytes without losing readability.

The app does not download or hot-swap external asset bundles: each approved image is reviewed, versioned and packaged in the APK. This is intentional for reliable offline local-first play.

## What testing actually proves (and what it does not)

**Automated:** app compiles with zero real artwork and keeps its procedural fallback; slot names are stable and mapped to all original/Lab v1/v2/v3 courses; packaging provenance validation; ordinary game tests and signed QA identity remain intact.

**Manual owner-phone acceptance still needed:** no deceptive fake roads, camera/zoom artifacts, contrast or text masking; no giant bitmap jank; no hidden important option under the new thumbnail; token numbers legible; game finishes properly; old saves preserved on install-over. A green CI result is **not** visual approval.

**Game design warning:** ARTREADY-38 is a production **pipeline**, not a claim that game feel and balance are solved. GAMEPLAY-37 interactive encounters, match length and real two-phone LAN still have separate acceptance gates. Do not merge main, claim Play Store readiness or copy sibling GridMates art without validating provenance and the other game's licenses.

## First review decision

When Batch A is installed, choose one of these specific actions based on real screenshots: **approve coherent style / revise contrast & clarity / revise overall art direction**. Only then create the rest of the set. The goal is a real artwork identity, not 12 placeholders with a different rendering method.
